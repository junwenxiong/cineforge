# 影铸白话词汇表

第一次接触拍电影或云端电脑？从这里看起。[返回 README](../../README.zh-CN.md) · [English](../en/glossary.md)

## 镜头（shot）

从开始到切换到下一个画面之间的一段连续视频。在影铸中，通常是一条单独生成的短片，常见长度为 5–6 秒。一场戏可以有很多镜头，例如先拍房间，再拍说话的人，再拍听者的反应。

## 景别（shot size）：画面里能看到多少

景别指主体在画面中占多大，不是视频有多少像素。从最远到最近，可以这样理解：

| 缩写 | 名称 | 能看到什么 |
|---|---|---|
| EWS / ELS | 大远景（extreme wide / long shot） | 大片风景，人可能只是一个小点 |
| WS / LS | 远景（wide / long shot） | 人物全身，以及较多周围环境 |
| FS | 全景（full shot） | 人物从头到脚 |
| MLS | 中远景（medium long shot） | 大约膝盖以上 |
| MS | 中景（medium shot） | 大约腰部以上 |
| MCU | 中近景（medium close-up） | 大约胸部以上 |
| CU | 特写（close-up） | 主要是脸 |
| ECU | 大特写（extreme close-up） | 眼睛、指尖等局部细节 |

这些是常见拍摄叫法，不是精确裁切尺寸，也不代表所有模型都会听话。拉近可以强调情绪，突然改变景别也可能让观众不舒服。先安排好变化，不要让每镜都变成大脸怼屏。目前 LTX 的生图说明默认偏向 MS/MCU；明确写 CU/ECU 才要求特写。其他景别仍需在提示词里写清楚，并人工检查。

## 参考图（reference image）

告诉模型人物、动物、道具或场景应该长什么样的图片，帮助不同镜头保持相同设计。每张参考图只画一个主体一次：同一只猫的两个视角，可能被模型理解成视频里要有两只猫。

## 首帧（keyframe）

在本项目的 LTX 流程中，指视频开始时的那张图片。一般参考图主要说明外观，首帧还决定开场姿势和构图。首帧里多出一只手，视频也可能跟着错，所以要先检查。

## H3

MiniMax-H3，一种能生成带声音视频的 AI 模型。本项目的快速 H3 方案使用用户另行取得许可的 DramaPie Box，可以参考多张图片。仓库不包含 Box 的实现代码。H3 自身还有模型许可和地区限制，见[模型说明](models.md)。

## LTX

LTX-2.5，另一种能生成视频和声音的 AI 模型。影铸用一张首帧引导它。distilled 是这套流程里较快版本的名称。不用 Box 可以走这条路线，但仍需配置 Colab，并接受所需的 Hugging Face 模型许可，见[模型说明](models.md)。

## Colab 运行时（runtime）

连接到 Google Colab notebook 的临时远程电脑。notebook 是放代码的网页，runtime 是真正执行代码的电脑。工作与上传结束后，要断开并删除运行时，再确认额度不再消耗。只关浏览器标签不能可靠地完成关机。

## GPU

图形处理器，一种能同时进行大量计算的芯片，负责生成视频时最费算力的部分。影铸预期通过 Colab 租用它，所以自己的电脑不必装高性能 GPU。G4 是原项目实测时显示的 GPU 选项名称，实际能否分配到会变化。

## 隧道（tunnel）

让 Colab 电脑通过互联网连到你本机电影服务的临时通道。地址和访问令牌要保密。重启后地址可能改变，传输中断时可能需要重试，见[农场指南](render-farm.md)。

## 渲染农场（render farm）

多台电脑一起给同一部电影生成镜头。这里的“渲染”就是生成视频。影铸的本地服务分配任务、收回短片，每台云端电脑同时只跑一个重型视频任务。电脑越多，消耗的付费额度也越多。

## 重拍（retake）

对没通过检查的镜头再生成一次。先修原因，例如参考图错误、动作不明确、构图不对，再重新生成。保留上一版，并确认没有电脑仍在处理这一镜，见[抽检与重拍](qa-and-retakes.md)。

## LUFS

全称 Loudness Units relative to Full Scale，用来衡量人听起来有多响。数值越接近零越响，例如 −10 LUFS 比 −20 LUFS 响。不同视频模型生成的声音可能差很多，剪辑时要调到协调的音量，再听有没有忽大忽小。LUFS 不能判断台词对不对、音乐好不好。
